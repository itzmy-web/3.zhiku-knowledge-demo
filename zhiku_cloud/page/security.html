SECURITY · 安全与合规

你的数据，始终在你手里

知识库往往装着企业最敏感的资料。我们把「数据自持」作为第一原则，并如实说明当前能力边界。

🔒 数据自持

已实现

私有化部署时，文档原文、向量库、会话历史全部保存在你自己的服务器（Milvus / MinIO / MongoDB），不经过第三方，可配置完全离线运行。

🛡 传输与存储加密

已实现

对外通信走 HTTPS；对象存储与向量库建议使用传输加密与静态加密；敏感配置（密钥、凭证）与环境变量隔离，不入库明文。

👥 权限与租户隔离

规划中

企业版规划：管理员 / 编辑 / 查看三级角色 + 知识库级访问控制；多租户检索强制带租户 ID 过滤，从底层杜绝跨租户检索泄露。

📜 审计日志

规划中

规划记录谁在何时访问 / 修改了哪份文档，满足企业合规与追溯需求；私有化部署可结合既有日志体系导出。

演示站安全提示（重要）：当前线上为公开共享的演示环境，任意手机号即可登录，数据不保证隔离与持久化。 请勿在演示站上传任何真实、涉密或个人隐私资料。需要安全使用时，请部署私有化版本，并把 Milvus / MinIO / MongoDB 的默认账号密码改为强密码。

隐私承诺

🚫 不上传第三方

私有化部署模式下，你的文档不会发送给任何第三方大模型 API（除非你主动配置并授权对应的模型服务）。

🧹 演示站不留存

演示站仅用于体验交互，不持久化你上传的真实内容；会话为临时态，刷新 / 重开即清空。

🔍 答案可追溯

产品目标：每个回答都标注引用来源（文档 / 页码），并在检索不到时明确提示「未找到」，而非编造。

⚙ 你掌握删除权

私有化部署时，文档、向量、会话的删除与备份完全由你控制，可随时清理或迁移。

部署安全建议

🔑 改默认密码

docker-compose 中的 Milvus / MinIO / MongoDB 默认账号密码务必改为强密码，避免裸奔暴露内网被接管。

💾 备份策略

定期备份 MinIO 原始文件、MongoDB 元数据与 Milvus 向量集合；etcd 为元数据关键组件，建议高可用部署并单独备份。

📡 网络收敛

向量库与数据库仅对内网开放，前端经反向代理暴露；不要将 Milvus / MongoDB 端口直接暴露在公网。

📈 监控告警

关注向量库内存占用（Milvus 建议 ≥16GB）与磁盘；小机器易 OOM，建议配置基础监控与告警。
