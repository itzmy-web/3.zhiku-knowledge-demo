## 排查并修复"查询阶段报错"（knowledge_base RAG 项目）

逐个复现、修复了查询流程（processor/query_processor）的 3 个阻塞性问题：

1. **pymilvus 版本不匹配（主因，import 即崩）**：pyproject.toml 锁定 `pymilvus[model]==2.3.*`（装出 2.3.8），但 `utils/milvus_utils.py` 用的是 2.4+ 才有的 `AnnSearchRequest`/`WeightedRanker`/`MilvusClient.hybrid_search`。已改为 `==2.5.*`（装 2.5.18），与服务端 v2.5.5 匹配，`uv sync` 已更新 uv.lock。
2. **ITEM_MODEL 模型名错误（隐性失败）**：.env 里 `ITEM_MODEL=qwen-flash` 是阿里云百炼命名，SiliconFlow 平台不存在 → 商品名提取 LLM 调用 400 被 except 吞掉 → 永远走"未找到相关产品"。已改为 `Qwen/Qwen3-8B`。
3. **BGE_DEVICE=gpu 非法**：PyTorch 只认 cuda/cpu → 向量生成 RuntimeError 导致整个查询图崩溃。已改为 `cuda`（本机 RTX 5060 可用，BGE_RERANKER_DEVICE 一并改）。

修复后完整查询链路（商品名确认→混合检索→HyDE→联网MCP→RRF→重排→生成）跑通，query_service 冒烟导入正常。

**遗留（非代码问题）**：Milvus 服务器 192.168.10.100:19530 上没有任何 collection（kb_item_names / kb_chunks 不存在），需先跑 import_processor 导入数据，否则查询永远返回"未找到相关产品"。

**已记录待修隐患**：node_web_search_mcp 无 try/except（MCP 故障会拖垮整图）；node_answer_output 拼接 content 为 None 会 TypeError；node_rrf entity 为 None 会 AttributeError；node_item_name_confirm 对 LLM 返回 null 的 item_names 会 len(None) 崩；base.py `state['session_id']` 方括号访问导致各节点 __main__ 单测 KeyError。
